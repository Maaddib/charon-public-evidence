# Publication checklist

The repository remains private and local until every item below is complete.

## Evidence accuracy

- [ ] Every dated claim is supported by a retained commit, Git object, file
      timestamp or clearly labelled retrospective evidence.
- [ ] Research experiments are not described as production capabilities.
- [ ] Current functionality is separated from historical functionality.
- [ ] Commit statistics have been rechecked against the private repositories.
- [ ] The chronology ends at the intended public cut-off date.

## Confidentiality

- [ ] No `.env`, credential, key, token or private infrastructure value.
- [ ] No real client, subject, person or company identifier.
- [ ] No case, evidence, source, artifact, collection or analysis UUID.
- [ ] No financial particulars or source-document contents.
- [ ] No usernames, hostnames, email addresses or local filesystem paths.
- [ ] No research corpus, quotations, source URLs or coded records.
- [ ] No commercially sensitive source, prompts, rules or thresholds.
- [ ] Image metadata and filenames reviewed.

## Repository safety

- [ ] Only reviewed paths are staged individually.
- [ ] `git status --short` and the staged diff have been reviewed.
- [ ] Full repository content and Git history have passed a secret scan.
- [ ] Repository description and topics contain no confidential wording.
- [ ] Public visibility is enabled only after explicit final approval.
- [ ] The published URL is tested in a logged-out browser session.

## Application integration

- [ ] Public URL added to the application brief.
- [ ] Public URL added to the CV.
- [ ] Both documents describe the repository as technical-development evidence,
      not as the complete Charon source repository.
